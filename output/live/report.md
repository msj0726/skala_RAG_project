# SUMMARY

시장에서는 MLA 계열의 서비스 운영과 CXL 계열의 제품 기반이 확인된다. 도메인에서는 MLA의 KV 절감만 정량화되며, 두 기술의 코딩 에이전트 응답성·비용은 근거 부족으로 판정을 유보했다. [S1] [S2] [S5] [S6]

# 1. 분석 배경

**긴 코딩 에이전트 세션은 KV cache의 저장·읽기 부담을 키운다.**

자기회귀 생성은 이전 토큰의 Key와 Value를 보관해 반복 계산을 줄인다. 코드·대화·도구 출력이 누적될수록 이 캐시가 커지므로, 세션당 캐시를 줄이는 MLA와 외부 메모리 수용량을 늘리는 CXL-PNM을 비교한다. [S1] [S2]

| 비교 관점 | DeepSeek-V2 MLA | CXL-PNM |
| --- | --- | --- |
| 병목 대응 | KV 표현을 저차원으로 압축 | KV 수용량 확장·근접 연산 |
| 변경 대상 | 모델 구조·서빙 커널 | 메모리 계층·서빙 경로 |

평가 기준일 2026-09-23 · 대상 AI 코딩·업무 에이전트 · 시장성/도메인 2개 관점

# 2. 기술 선정과 개요

**서로 다른 변경 지점을 대표하는 두 기술을 사람이 고정 선정했다.**

## Human 기반 고정 선정

선정 기준은 접근의 대표성, 요구 전제의 대조성, 두 관점의 자료 확보 가능성이다. 기술 조합을 고정해 실행 간 비교 가능성을 유지한다.

| 비교축 | DeepSeek-V2 MLA | CXL-PNM |
| --- | --- | --- |
| 핵심 접근 | KV를 저차원 잠재공간으로 압축 | CXL 메모리에 수용하고 근접 연산 |
| 요구 전제 | MLA 모델·대응 서빙 커널 | CXL-PNM 장치·드라이버·런타임 |
| 평가 초점 | 세션당 KV 예산 | 외부 KV 수용·선택 연산 |

## 2.1 SW: DeepSeek-V2 MLA

모델의 어텐션 구조를 바꾸는 방식이다. 기존 GPU에서 실행할 수 있지만 MLA 모델과 대응 커널이 필요해 임의 모델에 설정만으로 적용할 수 없다. [S1] [S3]

## 2.2 HW: 1M-Token LLM Inference의 CXL-PNM

CXL 메모리의 PNM 가속기로 KV 관련 선택·연산을 옮긴다. 선정 논문은 PNM-KV와 GPU 병행 방식 PnG-KV를 평가한다. PIM/CXL은 포괄 명칭이며 논문의 구체 방식은 PNM이다. [S2]

## 평가 단위

도메인 수치는 선정 논문 단위, 시장은 기술 계열까지 조사한다. CXL 제품·규격은 선정 PNM 구현의 상용 운영 증거로 간주하지 않는다. [S2] [S6] [S7]

# 3. 평가 방법

**시장성과 AI 코딩·업무 에이전트 적용성만 평가하며, 근거 부족은 숫자로 메우지 않는다.**

## 시장성: 성장·채택·생태계

| 기준 | 판정 방식 | 해석상 주의 |
| --- | --- | --- |
| M1 성장성 | 수요·채택 확대·공급 투자 각 0~2점; 합계 0~1 낮음, 2~3 보통, 4~5 높음, 6 매우 높음 | 3년 전망의 정성 평가이며 성장률 예측이 아님 |
| M2 채택 | 주체가 확인된 최고 단계: L4 운영, L3 제품, L2 PoC, L1 연구, L0 미확인 | 선정 기술과 기술 계열을 분리 |
| M3 생태계 | 프레임워크·제품·표준·제3자 도구의 Y 수: 3~4 L3, 1~2 L2, 원저자 구현만 L1, 모두 없으면 L0 | Y는 원문 청크로 확인; N은 부존재가 아닌 미확인 |

## 도메인: 수용성·응답성

| 기준 | 판정 방식 | 해석상 주의 |
| --- | --- | --- |
| D1 장기 세션 | 동일 조건 KV 예산·최대 문맥의 증가 배수: 4배 이상 L3, 2~4배 L2, 1~2배 L1, 개선·근거 없음 L0 | KV 감소율의 역수는 예산 환산치이지 실측 세션 길이가 아님 |
| D2 응답·비용 | 비용 절감+SLA 충족 시 TTFT·TPOT 지연 증가 0% 이하 L3, 10% 이내 L2, 초과 L1 | 절감 없음/SLA 미충족 L0; 필수 지표 누락은 판정 유보 |

M1 세부 항목과 D2 판정 유보는 과제 기준의 미정의 부분을 보완한 운영 규칙이다. 점수는 코드가 계산하고 원문 근거를 대조한다.

# 5. 도메인 평가 / AI 코딩·업무 에이전트

**MLA의 KV 절감은 정량화되지만, 두 기술 모두 코딩 에이전트의 응답 지연·비용은 판정할 근거가 부족하다.**

## D1 장기 세션 수용성

| 기술 | 판정 | 같은 조건의 근거와 한계 |
| --- | --- | --- |
| DeepSeek-V2 MLA | L3 | DeepSeek-V2 대 DeepSeek 67B의 KV cache 비교. 1/(1-0.933)=14.925배의 동일 KV 예산 환산치이며 실측 세션 길이 배수가 아니다. [S1] |
| CXL-PNM (PNM-KV / PnG-KV) | L0 | 최대 1M 문맥 실험은 확인되지만 128K→1M을 동일 하드웨어의 최대 문맥 증가 배수로 간주할 수 없다. GPU·PNM 수가 함께 바뀌며 기준 시스템도 CXL 확장 메모리를 사용한다. [S2] |

## D2 응답성과 비용

| 기술 | 판정 | 확인되지 않은 지표 |
| --- | --- | --- |
| DeepSeek-V2 MLA | 판정 유보 | 논문의 최대 처리량 향상을 TTFT·TPOT로 바꾸지 않는다. KV 감소율은 총 운영비 감소율이 아니다. 동일 코딩 에이전트 조건의 지연·비용·SLA 자료가 없다. [S1] |
| CXL-PNM (PNM-KV / PnG-KV) | 판정 유보 | 평가는 주로 decode 단계와 처리량/달러를 다룬다. 대화형 TTFT를 포함한 동일 SLA 비교가 없으므로 최대 비용 효율 수치만으로 D2를 확정하지 않는다. [S2] |

## AI 코딩·업무 에이전트에 적용할 때

| 기술 | 적용 해석 | 제약 |
| --- | --- | --- |
| DeepSeek-V2 MLA | 장기 세션당 KV 예산 감소에 연결되는 구조다. 실제 보존 가능한 코드·대화 길이는 모델 문맥 한도, 가중치 메모리, 동시 사용자, 도구 출력량에 함께 제약된다. | MLA 지원 모델과 커널이 필요하다. 일반 모델에 설정 하나로 적용하는 압축 기법이 아니다. 보고된 비교는 모델 구조가 다른 세대 간 비교이며 MLA만의 통제 실험으로 일반화하지 않는다. |
| CXL-PNM (PNM-KV / PnG-KV) | 여러 세션의 KV를 외부 메모리에 수용하고 선택 연산을 메모리 근처에서 처리하는 방향이다. 다수 에이전트의 동시 운용 가능성은 분석적 해석이며 코딩 에이전트 실측은 아니다. | 추가 CXL-PNM 하드웨어·드라이버·서빙 경로가 필요하다. 논문은 시뮬레이션 기반 성능 평가이며 요약 작업의 결과를 실제 도구 호출 세션에 직접 전이할 수 없다. |

장문맥 수용과 유효한 기억은 다르다. 코드 변경 추적·검색 정확도·도구 호출 성공률은 이 KV 비교만으로 검증되지 않는다.

# 6. 시사점과 한계

**시장 채택과 코딩 에이전트의 응답성·비용은 서로 다른 질문이므로 한 점수로 합치지 않는다.**

## 관점 사이의 차이

| 쟁점 | 해석 |
| --- | --- |
| 차이 1 | 시장 채택 단계가 높더라도 특정 코딩 에이전트의 응답 SLA 충족이 보장되지는 않는다. MLA 계열 서비스 존재와 D2 판정 유보는 모순되지 않는다. |
| 차이 2 | 외부 메모리 수용량의 확대와 토큰당 KV 압축은 서로 다른 변경 지점을 가진다. 동일 환경 실측 없이 양자의 수치를 직접 순위화하거나 합산하지 않는다. |
| 차이 3 | 계열의 제품·규격 지원은 연구 기술의 도입 기반이 될 수 있지만, PNM 논문 자체의 상용 운영 증거와 구분해야 한다. |

## 공개 정보와 평가 절차의 한계

| 구분 | 한계 |
| --- | --- |
| 한계 1 | 공개 자료와 벤더 자기보고를 사용했으며 독립적 실측은 수행하지 않았다. 상용 사용량·투자액·향후 3년 성장률은 확인하지 못했다. |
| 한계 2 | 시장 조사는 MLA 및 PIM/PNM·CXL 기술 계열로 넓혔다. 도메인 수치는 선정 논문 단위를 유지했다. PIM은 포괄 명칭이며 선정 논문의 구체 방식은 PNM이다. |
| 한계 3 | M1 세부 3항목과 D2 판정 유보 정책은 미정의 부분을 보완한 운영 규칙이다. M3에서는 동일 근거를 여러 범주에 중복 집계하지 않았다. |
| 한계 4 | 검색 원문에 근거 ID·페이지·범위를 연결하고, 긍정 주장과 제약을 함께 기록했다. 미확인 자료를 실패나 부존재로 단정하지 않으며 합산 승자를 만들지 않았다. |

## 실행 추적

원문 11개, PDF 실페이지와 웹 환산페이지 합계 169페이지(웹 3,000자당 1페이지). 임베딩 intfloat/multilingual-e5-small. 청크 ID·원문 해시·검색어·판정 입력은 evaluation.json에 기록했다.

실시간 검색 결과는 원문 검증 후 검토 원장과 대조한다. 일치하지 않는 모델 제안은 보고서에 반영하지 않는다. 재현 모드는 웹검색과 OpenAI 호출을 생략한다.
